# OntoLab documentation

The documentation imports the actual paper-theme tokens from `src/styles/helix.css` during preparation, so product and docs colors/fonts stay aligned without pulling application layout styles into Docusaurus.

Sample downloads are copied from the root application `samples/` directory before build/dev, keeping a single source of truth.

The docs have separate dependencies and a lockfile. Engineering notes live in the root `docs/` folder.

The app also bundles this source at `/docs/`. `npm run docs:bundle` from the repository root writes development help to `.data/bundled-docs/`; the API serves it through Vite's `/docs` proxy. `npm run build` and `npm run desktop:build` include documentation and Pagefind search in their distribution directories. Bundled help uses local assets, preserves the desktop content security policy, and provides a safe return link to the previous workspace. `BASE_PATH` prefixes are included in production builds. Standalone preview builds use `/ontolab/`.

## Local workflow

```bash
npm --prefix website ci
npm --prefix website start                 # http://localhost:3100/ontolab/
npm --prefix website run check             # Worker and local docs server routing checks
npm --prefix website run build             # strict links, static search, completeness checks
npm --prefix website run preview           # http://localhost:8788/ontolab/ (full production routing)
```

Search is generated by Pagefind after a production build; it needs no external service or key. The dev server does not generate that index. The Worker preview is the recommended final check: test desktop/mobile, search, downloaded samples, deep-link reload and unknown-page 404s.

## CI and preview

The Documentation workflow builds on pull requests and relevant pushes to
`main` and saves the checked site as an artifact. To test the local Worker
after a build, start the preview and run:

```bash
node website/scripts/smoke.mjs http://localhost:8788
```

The preview serves a hub at `/` and the docs under `/ontolab/`. Redirects
preserve the prefix, and unknown pages return HTTP 404.

## Content conventions

Use clear task-oriented titles, descriptions, relative Markdown links and sidebar entries. Verify instructions against app labels/types and label screenshots taken in local mock mode. Mark optional integrations and deployment-specific capabilities. Keep customer data, credentials, private operational logs and model prompts out of public assets. Update docs in the same PR as product behavior.

Dependencies override vulnerable build-tool versions of tinypool and serialize-javascript, and the development server's uuid dependency. The local docs server uses the small adapter in `vendor/minimatch-compat` to retain serve-handler's legacy API with patched minimatch 11. These versions are exercised by production/CI builds and routing checks. Low-severity deepmerge advisories remain in upstream build dependencies with no patched upstream release; no build dependencies are deployed as server code. The runtime Worker is the source in `worker/` plus public static assets.
